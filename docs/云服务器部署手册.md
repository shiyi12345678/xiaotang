# 直聘通 · 云服务器部署手册（A 方案）

> 目标：把「直聘通」部署到一台公网云服务器，产出一个**别人点开就能用**的链接（放进简历/发给面试官）。
> 本手册所有命令与配置键均已对照 `server/app/config.py`、`server/requirements.txt`、`.h5build/build.ps1` 实际核对。
> 编制时间：2026-09-22

---

## 〇、一页速览

**部署后的形态**

```
浏览器访问 https://你的域名  ──> Nginx ──┬── 静态文件：h5-preview/（前端 H5 产物）
                                        └── /api/ 与 /uploads/ ──> 127.0.0.1:8000（FastAPI + MySQL）
```

**为什么必须两台「服务」都在线**：本项目前端是纯静态资源，所有数据都来自后端 API；且项目**刻意不做 Mock 回落**（见 `README.md`），后端不通时页面会明确显示「加载失败」。只部署前端等于打开一个报错页。

**你需要准备的东西**

| # | 项目 | 说明 | 必需 |
| --- | --- | --- | --- |
| 1 | 云服务器 | 2 核 4G 起步（最低 2 核 2G 可跑，需关掉 RAG/图谱）；Ubuntu 22.04 或 24.04 | ✅ |
| 2 | MySQL 8 | 服务器上本地安装即可，不用单独买云数据库 | ✅ |
| 3 | 域名 + 备案 | **国内服务器必须备案才允许用 80/443**；香港/海外节点免备案 | ⚠️ 见第 1.2 节 |
| 4 | DeepSeek API Key | AI 求职助手用；**务必先在控制台设消费限额** | ✅ |
| 5 | 邮箱授权码 | 注册验证码用（如 QQ 邮箱 SMTP 授权码） | ✅ |
| 6 | 前端产物 | 本地跑 `.h5build/build.ps1` 生成 `h5-preview/` 后上传 | ✅ |

## 一、前置准备

### 1.1 服务器规格建议

| 配置 | 能否跑 | 说明 |
| --- | --- | --- |
| 2C2G | ✅ 可用 | **必须设 `RAG_ENABLED=false` 与 `GRAPH_ENABLED=false`**，否则内存不够 |
| 2C4G | ✅ 推荐 | 余量充足，MySQL + Python 同时跑无压力 |
| 1C2G | ⚠️ 勉强 | 编译/安装依赖时容易 OOM，可先加 swap |

> ⚠️ **RAG / 图谱相关功能关闭后，`/api/v1/ai/rag/status`、`/api/v1/ai/graph/status` 会显示不可用，AI 求职助手仍可正常问答（走纯大模型链路）。** 不要在低配服务器上强行启用 Milvus/Neo4j（内存需求 4G+）。

### 1.2 域名与备案（**最容易拖慢进度的一步，先决策**）

| 情形 | 最终链接长什么样 | 备注 |
| --- | --- | --- |
| 国内服务器 + **已备案**域名 | `https://zhaopin.xxx.com` | 体验最好；备案约 1~2 周 |
| 国内服务器 + 未备案 | `http://1.2.3.4:8080` | 只能走非 80/443 端口；浏览器会提示「不安全」，微信内可能打不开 |
| **香港/海外**轻量服务器 + 域名 | `https://zhaopin.xxx.com` | **免备案**，国内访问速度尚可，是学生项目最省事的组合 |
| 完全不要域名 | `https://1.2.3.4` | 需要自签证书，浏览器会红警告，**不推荐发给别人** |

> **建议**：如果只是简历展示、且不想等备案，选「香港/海外轻量 + 域名 + Let's Encrypt 免费证书」。

### 1.3 你需要先填好的信息（后面命令里会用到）

| 变量 | 示例 | 你的值 |
| --- | --- | --- |
| `SERVER_IP` | `1.2.3.4` | |
| `SSH_USER` | `ubuntu` / `root` | |
| `DOMAIN` | `zhaopin.example.com`（没有域名就留空） | |
| `DB_PASSWORD` | 强密码（字母+数字+符号） | |
| `JWT_SECRET` | 新生成的随机串（见第 5 节） | |
| `AI_API_KEY` | `sk-xxxx`（DeepSeek） | |
| `SMTP_USER` / `SMTP_PASSWORD` | 邮箱账号 / 授权码 | |

## 二、服务器环境安装（Ubuntu 22.04 / 24.04）

```bash
# 1) 更新系统
sudo apt update && sudo apt upgrade -y

# 2) 安装 Python、MySQL、Nginx、git、编译工具
sudo apt install -y python3 python3-venv python3-pip git nginx mysql-server build-essential pkg-config default-libmysqlclient-dev

# 3) 确认版本（本项目要求 Python ≥ 3.11）
python3 --version
mysql --version
nginx -v
```

> ⚠️ 若 `python3 --version` 低于 3.11（如 Ubuntu 22.04 自带 3.10），需要另装 3.11+（`sudo apt install -y python3.11 python3.11-venv`），并把后面所有 `python3` 换成 `python3.11`。

**初始化 MySQL（安全加固）**

```bash
sudo mysql_secure_installation      # 按提示设置 root 密码、删除匿名用户、禁止远程 root 登录
```

## 四、建库与灌入种子数据

```bash
# 1) 登录 MySQL
sudo mysql -u root -p

# 2) 创建数据库与业务账号（不要用 root 跑业务）
CREATE DATABASE sheji DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'zhipin'@'127.0.0.1' IDENTIFIED BY '第 1.3 节的 DB_PASSWORD';
GRANT ALL PRIVILEGES ON sheji.* TO 'zhipin'@'127.0.0.1';
FLUSH PRIVILEGES;
EXIT;
```

> ⚠️ **高危提示**：以下两条命令执行 `CREATE TABLE`（DDL）与批量写入。
> 1. 只能对**刚创建的空库**执行，绝对不要指向任何已有数据的库；
> 2. 执行前请确认数据库可回滚（云数据库建议先打快照；自建库可 `mysqldump` 备份）：
>    `mysqldump -u root -p sheji > ~/sheji_backup_$(date +%F).sql`
> 3. 本手册**不包含任何 DROP / TRUNCATE 语句**；重置演示数据请使用项目自带脚本（见下）。

```bash
cd ~/zhipintong/server

# 3) 准备虚拟环境并安装依赖
python3 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt

# 4) 建表（只创建尚不存在的表，不会改动已有表结构）
.venv/bin/python -m app.init_db

# 5) 灌入招聘种子数据（内容 + 演示职位/公司/题库）
#    ⚠️ 不要加 --full：--full 会连用户产生的投递/收藏/会话一起清空
.venv/bin/python -m app.seed_recruit
```

> 首次执行 `init_db` / `seed_recruit` 前必须先有第 5 节的 `.env`（`config.py` 里 `DB_PASSWORD`、`JWT_SECRET` 是必填项，缺失会直接启动失败）。

## 五、后端配置文件 `.env`

在服务器上创建 `~/zhipintong/server/.env`：

```ini
# ---------- 数据库 ----------
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=zhipin
DB_PASSWORD=第 1.3 节的强密码        # ⚠️ 必填，config.py 无默认值
DB_NAME=sheji

# ---------- 鉴权（必填）----------
# ⚠️ 必须重新生成，禁止复用本机那个：生成命令见下方
JWT_SECRET=第 1.3 节生成的随机串
JWT_EXPIRE_DAYS=7

# ---------- AI 求职助手 ----------
AI_API_KEY=sk-你的DeepSeek密钥
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-v4-flash
AI_TIMEOUT=180

# ---------- 邮箱验证码 ----------
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=你的邮箱@qq.com
SMTP_PASSWORD=邮箱SMTP授权码
SMTP_FROM_NAME=直聘通
EMAIL_CODE_LEN=4
EMAIL_TTL=300
EMAIL_INTERVAL=60                    # 60 秒内不得重发，防刷
EMAIL_DEBUG=false                    # ⚠️ 公网必须 false，true 会把验证码打在日志里

# ---------- 低配服务器：关闭重依赖 ----------
RAG_ENABLED=false                    # 无 Milvus 时关闭
GRAPH_ENABLED=false                  # 无 Neo4j 时关闭
```

生成新的 `JWT_SECRET`（任选一条执行）：

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
# 或
openssl rand -base64 48
```

设置文件权限（防止同机其他用户读到密钥）：

```bash
chmod 600 ~/zhipintong/server/.env
```

## 六、后端常驻运行（systemd）

不要让 uvicorn 挂在 SSH 会话里（断开会话服务就停）。用 systemd 托管：

```bash
sudo nano /etc/systemd/system/zhipintong-api.service
```

```ini
[Unit]
Description=ZhiPinTong FastAPI Backend
After=network.target mysql.service

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/zhipintong/server
# ⚠️ 生产环境不要加 --reload（会额外占用内存并监听文件变化）
ExecStart=/home/ubuntu/zhipintong/server/.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
Restart=always
RestartSec=3
# 日志进 journald，用 journalctl -u zhipintong-api -f 查看
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

> ⚠️ 把 `User`、`WorkingDirectory`、`ExecStart` 里的 `ubuntu` 与路径换成你的实际用户名与路径（用 `whoami`、`echo $HOME` 确认）。
> 后端只监听 `127.0.0.1:8000`，由 Nginx 对外，**不要把 8000 端口直接暴露到公网**。

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now zhipintong-api
sudo systemctl status zhipintong-api          # 应为 active (running)
curl http://127.0.0.1:8000/api/v1/job/home    # 应返回 {"code":0,...} 含职位数据
```

## 八、Nginx 配置（静态托管 + 反向代理）

```bash
sudo nano /etc/nginx/sites-available/zhipintong
```

```nginx
server {
    listen 80;
    server_name zhaopin.example.com;      # 没有域名就写服务器公网 IP

    # ---------- 前端静态资源 ----------
    root /home/ubuntu/zhipintong/h5-preview;
    index index.html;

    # uni-app H5 使用 hash 路由，所有页面都在 index.html#... 之下，
    # 因此只需要把根路径交给 index.html 即可，无需 history 回退规则。
    location / {
        try_files $uri $uri/ /index.html;
    }

    # ---------- 后端接口 ----------
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # ⚠️ 这两行是 AI 对话流式输出（SSE / WebSocket）必需，漏掉会出现「AI 不回答」
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 300s;
        proxy_buffering off;
    }

    # ---------- 用户上传的图片 ----------
    location /uploads/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
    }

    # 静态资源缓存（可选优化）
    location ~* \.(js|css|ttf|woff2?|png|jpg|svg)$ {
        expires 7d;
        add_header Cache-Control "public";
    }
}
```

启用并重载：

```bash
sudo ln -s /etc/nginx/sites-available/zhipintong /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default      # 移除默认站点，避免抢占 80 端口
sudo nginx -t                                    # 配置语法检查，必须 success
sudo systemctl reload nginx
```

> ⚠️ `root` 指向的是**你家目录**下的文件，Nginx 默认以 `www-data` 运行，需要保证它有权读取：
> ```bash
> chmod 755 /home/ubuntu            # 家目录可进入
> chmod -R 755 /home/ubuntu/zhipintong/h5-preview
> ```
> 若仍报 403，检查 `/var/log/nginx/error.log`，通常是权限或 SELinux 问题。

## 九、HTTPS（有域名时必做）

```bash
# 1) 安装 certbot
sudo apt install -y certbot python3-certbot-nginx

# 2) 自动签发并改写 Nginx 配置（把域名换成你的）
sudo certbot --nginx -d zhaopin.example.com

# 3) 自动续期测试（Let's Encrypt 证书 90 天有效）
sudo certbot renew --dry-run
```

> ⚠️ **为什么必须 HTTPS**：前端一旦跑在 `https://` 下，浏览器会拦截它向 `http://` 后端发起的请求（Mixed Content 混合内容），表现为页面转圈或加载失败，且控制台错误不具备友好提示，极易误判为「后端没启动」。本手册用**同源**（`/api/v1` 相对路径）从根上规避了这个问题。

**没有域名时**：跳过本节，只能用 `http://SERVER_IP:8080` 形式访问（把 Nginx 的 `listen 80` 改成 `listen 8080`，并在云厂商安全组放行 8080）。简历里放这种链接体验较差，建议尽早补域名。

## 十一、常见故障排查

| 现象 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 打开链接是白页/目录列表 | Nginx `root` 指错，或 h5-preview 未上传 | `ls ~/zhipintong/h5-preview` 确认有 `index.html` 和 `assets/` |
| 页面显示「加载失败，点击重试」 | 后端没起，或 `/api/` 反代不通 | `curl 127.0.0.1:8000/api/v1/job/home`；`journalctl -u zhipintong-api -n 50` |
| 请求报 404 且路径重复 | `PROD_BASE_URL` 与 Nginx 的 `location /api/` 叠加（如 `/api/v1/api/v1/...`） | `PROD_BASE_URL` 保持 `/api/v1`，Nginx 用 `proxy_pass http://127.0.0.1:8000;`（**末尾不要加斜杠**） |
| 控制台报 Mixed Content | 前端 https 却请求 http 后端 | 改用同源相对路径，或给后端配 https |
| 图片不显示（AI 上传图） | 漏配 `/uploads/` 反代 | 补上第 8 节的 `location /uploads/` 并 reload |
| 服务启动即退出 | `.env` 缺 `DB_PASSWORD` / `JWT_SECRET`（`config.py` 必填项） | `journalctl -u zhipintong-api -n 50` 看报错 |
| 登录 500 / 连不上库 | MySQL 账号只授权了 `127.0.0.1`，而连接串用了 `localhost` | `.env` 里 `DB_HOST=127.0.0.1` |
| 服务器内存爆掉 | 开了 Milvus/Neo4j | 保持 `RAG_ENABLED=false`、`GRAPH_ENABLED=false` |

## 十二、上线后的风险与成本

### 12.1 必须处理的风险

1. **AI API Key 会被陌生人消耗** ⚠️ 最严重
   链接是公开的，任何人都能用 AI 求职助手。
   **必做**：去 DeepSeek 控制台设置**消费限额**（零代码改动，最有效）；建议再申请一个**演示专用 Key**，与主 Key 分离。
2. **邮箱被注册流程刷爆**
   公开链接意味着任何人可反复触发验证码。**建议**：用专门的演示邮箱（不要主邮箱）；保持 `EMAIL_INTERVAL=60`；必要时在控制台给 SMTP 账号设发送配额。
3. **数据库被写入脏数据**
   任何人都能注册、投递、收藏。**建议**：定期用 `python -m app.seed_recruit`（**不加** `--full`）刷新内容数据；若确需回到全新演示态再用 `--full`，⚠️ 它会清空用户产生的投递/收藏/会话，执行前务必先 `mysqldump` 备份。
4. **密钥安全**
   `.env` 权限设为 `600`；`JWT_SECRET` 与数据库密码必须与本地不同；不要把 `.env` 提交进 Git。
