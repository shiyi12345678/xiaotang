# 招聘改造 · 前端页面公约（所有页面必须遵守）

> 本文件是 2026-09-19「学习类 App → 招聘 App（直聘通）」改造时定的前端统一约定。
> 新增或改造任何页面之前先读本文件，避免各页面各写一套。

---

## 一、技术基线

- **uni-app（Vue 3）× Options API**：现有 19 个页面全部是 `export default { ... }` 写法，
  一律沿用，**不要用 `<script setup>`**（混用会让生命周期与 `this` 的写法在两套心智模型间跳动）。
- 页面结构：`<template>` + `<script>`（`name` / `props` / `data` / `onLoad` / `onShow` / `methods`）+ `<style lang="scss" scoped>`。
- 接口调用**只走 `services/` 下的封装**（`job.js` / `apply.js` / `hr.js` / `interview.js` / `im.js` / `user.js` / `chat.js` / `content.js`）。
  不要在页面里自己拼 URL，也不要直接 `import { request } from '@/services/api.js'`。

## 四、数据与状态（最容易被忽略、也最影响体验的三条）

1. **三态齐全**：任何拉数据的页面都必须处理
   「加载中」（骨架或 `正在加载…`）、「空数据」（`<zn-empty>`）、「加载失败」（可点击重试）。
2. **不做 mock 回落**：接口失败就是失败，**不要**自己编造兜底数据、也不要静默吞掉错误。
   本项目刻意如此设计——接口不通时就应该看见失败，而不是看见假数据。
3. **列表页统一**：`onPullDownRefresh`（并在 `pages.json` 配 `enablePullDownRefresh`，配置由负责人统一改）
   + `onReachBottom` 触底加载；分页参数用 `page` / `pageSize`，服务端返回 `hasMore`。

## 五、注释与文案

- 中文注释，讲**为什么**（取舍、坑、非显然之处），不写 `// 获取数据` 这类废话，也不留 TODO。
- 界面文案统一招聘语境：职位 / 投递 / 简历 / 面试 / 沟通 / 内推；
  不要再出现「课程」「讲师」「报名」「学习」「题库（学科）」等学习端词汇。

## 七、页面展示型配置的取法

招聘端的轮播、宫格、筛选选项、报告模板等**展示型数据**存在 `page_config` 表里，
键名以 `rc` 开头（如 `rcHeroBanners` / `rcMineGridGroups` / `rcSeekerReport` / `rcLoginConfig`）。
读取方式沿用既有接口：

```js
import { getConfig } from '@/services/content.js'
const groups = await getConfig('rcMineGridGroups')   // 取不到会 reject，可有可无的配置请自行 catch
```

已种子的键：`rcHeroBanners` `rcHomeEntries` `rcHomeNotices` `rcHotKeywords` `rcFilterOptions`
`rcJobListTabs` `rcJobDetailTabs` `rcMineStats` `rcMineGridGroups` `rcHrMineGridGroups`
`rcSettingGroups` `rcLoginConfig` `rcAiWelcome` `rcAiCapabilities` `rcSeekerReport`
`rcHrDashboard` `rcReferralZone`。

> 注意：`/api/v1/job/home` 与 `/api/v1/job/filters` 已经把其中几个键包装成了业务语义的返回
> （`banners` / `entries` / `notices` / `hotKeywords` / `listTabs`、`filters.kinds`），
> 能用这两个接口就不必再单独读配置。
