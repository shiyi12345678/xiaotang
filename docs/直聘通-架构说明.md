# 直聘通 · 招聘 App 架构说明

> 本文档记录 2026-09-19「学习类 App（网易云课堂风格）→ 招聘 App（直聘通）」的改造结果。
> 目标是让后来者（包括未来的自己）能在不理解全部代码的前提下，快速搞清楚**数据在哪、接口在哪、状态怎么流转、怎么回滚**。

---

## 一、一句话概括

- **前端**：uni-app（Vue 3 · Options API）× 求职者端 + 企业 HR 端，零图片资源（一律渐变/色块/`uni-icons` 占位）
- **后端**：FastAPI + SQLAlchemy 2.0 async，统一响应 `{code, msg, data}`（成功码是 `0`，消息字段是 `msg`）
- **存储**：MySQL（业务数据）、Milvus（RAG 向量库）、Neo4j（知识图谱）、Redis 未使用
- **主题**：主色 `#00A6A7`（青绿），变量名仍是历史遗留的 `zn-` 前缀（只改值不改名，避免几百处重命名）

## 二、双身份（本项目最容易看错的一点）

账号体系**完全复用改造前的 `user` 表**（注册 / 登录 / 邮箱验证码 / JWT 一行没改），
身份信息单独放在新表 `user_role` 里：

```
user_role(user_id, role, company_id, hr_title, is_default)
    role = 'candidate' → company_id 为 NULL（求职者）
    role = 'hr'        → company_id 必须指向一家公司（招聘方）
```

- 同一账号可以**同时**拥有两种身份，`(user_id, role)` 唯一但允许两条并存。
- 企业端所有接口都先过 `_hr_context()` 这道闸门（`server/app/routers/hr.py`）：
  没绑定公司就返回 403（`40301`）。因此「未绑定公司看不到任何招聘数据」是**结构性保证**，不靠各处自觉。
- 绑定公司（`POST /api/v1/hr/bind`）会**接管该公司名下没有归属招聘者的职位**（把 `job.hr_id` 指向当前账号），
  否则求职者点「立即沟通」找不到聊天对象。

## 三、数据模型（13 张新表，旧表全部保留）

| 分组 | 表 | 说明 |
| --- | --- | --- |
| 角色 | `user_role` | 见上 |
| 主体 | `company` `city` `job_category` `job` `job_favorite` | 职能分类两级（`level` 1 大类 / 2 子类） |
| 流程 | `resume` `application` `interview` `conversation` `message` | 简历 / 投递 / 面试邀约 / 会话 / 消息 |
| 备考 | `interview_question` `question_record` | 面试题库 / 刷题记录 |

**共用表**（复用而非新建）：`user` `email_code` `sms_code` `ai_session` `ai_message` `page_config`。

关键设计取舍（都写在对应模型文件的注释里）：

- **薪资存「整数 K + 几薪」**，不存字符串：`salary_min/salary_max`（单位 K）+ `salary_months`，
  展示文案 `25-45K·15薪` 由 `server/app/schemas/job.py` 的 `salary_text()` 统一拼，
  保证列表页、详情页、投递快照三处口径一致。
- **投递行存职位快照**（`job_title` / `company_name` / `salary_text`）：
  职位改名或下架后，求职者仍能看到自己当时投的是什么。
- **会话行冗余「最后一条消息 + 未读数」**：会话列表因此不需要扫 `message` 表。
- **简历的教育/工作/项目经历存 JSON 数组**：它们永远整体读写，拆三张子表只会增加联表成本。
- **`page_config` 只覆盖 `rc` 前缀的键**：学习端的键（`banners`/`mineGridGroups`/`aiWelcome`…）原样保留，
  所以旧前端随时可以切回去。

## 四、接口地图（40 条招聘路由）

| 前缀 | 条数 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| `/api/v1/job` | 10 | 浏览公开 / 收藏 🔒 | 首页聚合、列表与搜索、详情、分类、城市、筛选、收藏 |
| `/api/v1/apply` | 5 | 🔒 | 投递、我的投递、投递详情、撤回、求职中心统计 |
| `/api/v1/resume` | 3 | 🔒 | 我的简历、保存、求职报告 |
| `/api/v1/hr` | 13 | 🔒 | 身份与绑定、工作台、职位增删改查、收到简历、候选人详情、状态流转、面试邀约、面试安排、公司信息 |
| `/api/v1/chat` | 6 | 🔒 | 会话列表、发起沟通（幂等）、消息收发、标记已读、未读合计 |
| `/api/v1/interview` | 6 | 题库公开 / 记录 🔒 | 题库分类、题目列表与详情、提交作答、薄弱点、刷题进度 |

**旧学习端接口全部保留可访问**（`/api/v1/content`、`/api/v1/mine`、`/api/v1/study`、`/api/v1/ai`），
这是回滚保证的一部分。

## 五、状态机（唯一实现处：`server/app/schemas/hr.py`）

```
submitted 已投递 → viewed 简历已查看 → chatting 沟通中 → interview 待面试
      → passed 面试通过 → hired 已入职
任意阶段可走向 rejected 不合适；submitted/viewed/chatting 阶段求职者可 withdrawn 撤回
hired / rejected / withdrawn 为终态
```

- 用「**允许集合**」而不是「禁止集合」描述：新增状态时允许集合默认拒绝（安全），禁止集合默认放行（危险）。
- `interview` 只能由「发面试邀约」接口设置，避免出现「状态是待面试却没有任何邀约记录」的脏数据。
- 前端把按钮置灰只是体验优化，**服务端一定会再拦一次**（非法流转返回 409 / `40910`）。

## 六、展示型配置（17 个键）

轮播、职能入口、筛选选项、宫格、报告模板、AI 欢迎语等纯展示数据放在 `page_config`，
键名统一以 `rc` 开头：

```
rcHeroBanners rcHomeEntries rcHomeNotices rcHotKeywords rcFilterOptions rcJobListTabs
rcJobDetailTabs rcMineStats rcMineGridGroups rcHrMineGridGroups rcSettingGroups
rcLoginConfig rcAiWelcome rcAiCapabilities rcSeekerReport rcHrDashboard rcReferralZone
```

读取方式：`GET /api/v1/content/config/{key}`（沿用改造前的通用配置接口）；
其中 `banners/entries/notices/hotKeywords/listTabs` 已被包装进 `/api/v1/job/home`，
筛选选项被包装进 `/api/v1/job/filters`，能用业务接口就不必单独读配置。

## 八、RAG 知识库

AI 求职助手走的是「向量检索（Milvus）+ 知识图谱（Neo4j）」混合检索，知识块来自招聘种子数据：
职位 JD、公司信息、面试题与参考答案、平台规则与求职建议。
集合名在 `server/.env` 的 `MILVUS_COLLECTION`（招聘改造后为 `job_kb_v1`）。

> ⚠️ 改造前它装的是**课程**知识。若发现 AI 答非所问地讲课程，先检查集合名与灌库来源。

## 九、回滚（改造是全量隔离的）

想切回学习类 App，需要做的事只有一件：**把 `pages.json` 换回旧的页面清单**。

- 旧页面文件（`pages/category`、`pages/study/*`、`pages/course/detail`、`pages/search`、
  `pages/mine/my-course`、`pages/mine/order`）在磁盘上原样保留；
- 旧服务层（`services/study.js`、`services/mine.js`、`services/content.js`）与
  `common/utils/study-store.js` 原样保留；
- 旧数据库表（`course` / `order_info` / `question` / `page_config` 旧键 …）一行数据都没动；
- 旧接口（`/api/v1/content`、`/api/v1/study`、`/api/v1/mine`）照常可访问。

**唯一不可逆的是主题色与应用名**（`uni.scss` / `manifest.json` / `pages.json` 的全局标题），
改回 `#4cd964` / 「网易云课堂」即可。

## 十、启动方式（日常）

```powershell
# 后端：登录 Windows 后由「启动」文件夹的快捷方式自动以隐藏窗口拉起
#       手动停止：server\backend_stop.bat    查看日志：server\backend_log.bat
#       调试用（带 --reload 与实时日志）：server\start_server.bat

# 前端：HBuilderX → 运行 → 运行到浏览器
#       前端会自动推断后端地址（取地址栏主机名 + 8000 端口），换 IP / 换网段都不用改配置

# RAG 依赖（AI 求职助手需要）：
#   先启动 Docker Desktop，再
cd server\docker
docker compose -f milvus-compose.yml up -d     # 若报容器名冲突，改用 docker start milvus-etcd milvus-minio / milvus-standalone
```
