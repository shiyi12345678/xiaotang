# 直聘通 · IP 直连部署清单（不买域名的方案）

> 目标：部署完成后得到 `http://服务器公网IP:8080`，别人点开即可使用。
> 适用：只做临时演示 / 不想花钱买域名。
> ⚠️ 前置条件：**必须有一台带公网 IP 的云服务器**（腾讯云/阿里云轻量等，2C2G 起）。
>    自己的电脑能拿到公网 IP 的情况极少（国内家宽普遍无公网 IP，且运营商封禁 80/443），不要指望端口映射。
> 通用步骤（装环境、建库、灌数据、systemd 常驻、风险提示）与 `docs/云服务器部署手册.md` 完全一致，本文只写**差异部分**。

---

## 一、与域名方案的差异（只有 3 处）

| 项目 | 域名方案 | IP 直连方案 |
| --- | --- | --- |
| Nginx 监听端口 | `80` / `443` | **`8080`**（避开未备案的 80 端口） |
| 访问地址 | `https://你的域名` | `http://IP:8080` |
| HTTPS 证书 | certbot 一键签发 | **签不了**（普通免费证书不支持 IP），只能走 http |

**其余全部相同**，且前端 `PROD_BASE_URL` 用相对路径 `/api/v1` 的设计在这里同样有效——
将来补上域名时，**前端产物不用重新构建**，只改 Nginx 配置即可升级到 https。

---

## 二、必须放行的端口

云厂商控制台 → 安全组（防火墙）→ 入站规则放行：

| 端口 | 用途 | 是否必需 |
| --- | --- | --- |
| `8080` | 前端页面 + 后端接口（Nginx 统一入口） | ✅ 必需 |
| `22` | SSH 登录 | ✅ 必需（一般默认已开） |
| `8000` | 后端 uvicorn | ❌ **不要放行**（只让 Nginx 内网访问） |

> ⚠️ 常见错误一：只放行了 22，结果 8080 打不开，浏览器表现为"连接超时"。
> ⚠️ 常见错误二：图省事把 8000 也放行到公网——会让后端直接暴露在公网，没有必要。

---

## 三、部署步骤（与手册的差异处）

前 5 步（装环境 → 上传代码 → 建库灌种子 → 写 `.env` → systemd 常驻）**完全照 `docs/云服务器部署手册.md` 第二~六节执行**，此处不重复。差异在 Nginx 配置与前端地址：

### 3.1 前端地址（需你确认后我才改）

`common/config.js` 第 39 行附近：

```js
// 同源部署：相对路径，IP 换端口、将来换域名都不用重新构建
const PROD_BASE_URL = '/api/v1'
```

改完执行本地构建，再上传产物：

```powershell
cd "D:\cheng du shi xi\ai she ji"
powershell -File .h5build\build.ps1      # 产物同步到 h5-preview/
```

```bash
scp -r "D:/cheng du shi xi/ai she ji/h5-preview" $SSH_USER@$SERVER_IP:~/zhipintong/
```

> **备选（不改代码）**：保持 `PROD_BASE_URL = ''`，前端会按"打开页面的主机名 + 8000 端口"自动推断后端地址，
> 即请求 `http://IP:8000/api/v1`。这要求**额外放行 8000 端口**且后端监听 `0.0.0.0`（把 systemd 的 `--host 127.0.0.1` 改成 `--host 0.0.0.0`）。
> 优点是不用改代码；缺点是后端直接暴露公网、多开一个端口。**推荐用上面的同源方案。**

### 3.2 Nginx 配置

把 `docs/deploy/nginx-ip-8080.conf` 上传到 `/etc/nginx/sites-available/zhipintong`，然后：

```bash
sudo ln -sf /etc/nginx/sites-available/zhipintong /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default      # 移除默认站点，避免抢占端口
sudo nginx -t                                    # 语法检查，应为 success
sudo systemctl reload nginx
```

### 3.3 确认后端仍在监听本地回环

```bash
curl http://127.0.0.1:8000/api/v1/job/home       # 应返回 {"code":0,...} 且含职位数据
```

| 1 | 服务器上 `curl http://127.0.0.1:8080/` | 返回前端 `index.html` 内容 |

## 五、IP 方案的四个限制（提前知道，避免踩坑）

1. **没有 HTTPS** —— 浏览器地址栏会显示"不安全"；微信内打开 http 链接可能出现安全提示页（多数情况点"继续访问"即可）。
2. **IP 可能变** —— 如果服务器没绑定弹性公网 IP，重装系统、更换实例后 IP 会变，链接随之失效。绑定弹性 IP 可避免（一般免费或几元/月）。
3. **观感一般** —— 简历上写 `http://111.229.130.56:8080` 不如域名正式，面试官也无法一眼判断这是什么项目。
4. **无法用 CDN、不被搜索引擎收录**，后续想做这些都绕不开域名。

## 六、将来想升级成域名（只需 3 步，前端不用动）

因为前端用的是相对路径 `/api/v1`，升级域名时**不需要重新构建前端**：

1. 买域名并解析到服务器 IP（见 `docs/deploy/` 与手册第九节）
2. 把 Nginx 的 `listen 8080;` 改回 `listen 80;`，并填上 `server_name 你的域名;`
3. `sudo certbot --nginx -d 你的域名` 自动配好 https

完成后链接即从 `http://IP:8080` 变为 `https://你的域名`，页面与数据完全不受影响。
