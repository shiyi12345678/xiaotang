# 公网部署方案 · 让项目可通过链接在浏览器中使用

> 目标：生成一个公开链接，放进简历，面试官点击即可在浏览器中使用该项目
> 现状核查时间：2026-09-17
> 结论：**可行，但"完整可用"的代价比预期高，且有 4 个必须先解决的坑**

---

## 一、先说结论

**三条路径，我的推荐顺序是：PaaS 部署 ＞ 云托管 ＞ 自建服务器。**

但更重要的一点：**"完整可用"意味着你的 DeepSeek API Key 和邮箱会被公开链接上的任何陌生人消耗。** 这是本方案最大的非技术风险，第五节给了缓解办法，请务必看完再决定。

---

## 二、现状诊断：为什么现在直接部署不行

| 事实 | 证据 | 后果 |
| --- | --- | --- |
| 构建产物里硬编码了局域网地址 | `h5-preview/assets/api.BgaWQzLf.js` → `192.168.6.20:8000` | 公网打开必然「网络连接失败」 |

| 静态托管平台不支持后端 | 部署通道文档明确：不支持后端 API、数据库、常驻进程 | 必须先有独立的公网后端 |

**根本矛盾**：这是一个前后端分离项目，前端是静态资源、后端是 FastAPI 常驻服务。链接要能用，两者都得在线，且必须能互相访问。

## 四、实施步骤

### 阶段 1：准备公网后端运行环境

选择下列三条路径之一（见第六节对比表）：

- **路径 A（PaaS）**：注册 Railway / Render / Fly.io，创建 Python 服务
- **路径 B（云托管）**：用腾讯云 CloudBase 云托管，需先写 Dockerfile
- **路径 C（自建）**：买一台海外轻量服务器（免备案），自行安装 Python 3.13 + MySQL 8 + Nginx

### 阶段 2：准备数据库

1. 创建 MySQL 8 实例与数据库 `sheji`
2. 创建业务账号，**不要用 root**
3. 上传 `server/` 代码后执行建表与灌种子数据：

```bash
python -m app.init_db    # 建表
python -m app.seed       # 写入种子数据
```

> ⚠️ 这两条命令会创建表结构，属于 DDL 操作，执行前请确认目标是新库。**请先备份**，不要指向任何已有数据的库。

### 阶段 3：配置环境变量

在服务器上创建 `.env`（**不要提交到任何版本库**），至少包含：

```ini
# ---------- 数据库 ----------
DB_HOST=你的数据库地址
DB_PORT=3306
DB_USER=业务账号
DB_PASSWORD=强密码
DB_NAME=sheji

# ---------- 鉴权 ----------
JWT_SECRET=重新生成的随机长字符串    # ⚠️ 不要复用本地这个，公网部署必须换新

# ---------- AI 助教 ----------
AI_API_KEY=你的DeepSeek密钥
AI_BASE_URL=https://api.deepseek.com

# ---------- 邮箱验证码 ----------
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=你的邮箱
SMTP_PASSWORD=邮箱授权码

# ---------- 可选依赖开关 ----------
RAG_ENABLED=false      # 无 Milvus 时关闭
GRAPH_ENABLED=false    # 无 Neo4j 时关闭
```

> ⚠️ **`JWT_SECRET` 必须换成新的随机值**。沿用本地那个等于把本地登录态的签发密钥公开到公网，任何人都能伪造 token。

### 阶段 4：配置 HTTPS（**最容易翻车的一步，务必看**）

这是整个方案里最隐蔽的坑：

- 静态托管平台分给你的链接通常是 **https**
- 后端如果只有 `http://1.2.3.4:8000`，浏览器会以 **Mixed Content（混合内容）** 为由**直接拦截请求**，控制台报错，页面上表现为转圈或加载失败
- 而且这个错误**不会**给出"请确认服务端已启动"这类友好提示，排查时容易被误导

三个解法：

| 解法 | 做法 | 适用 |
| --- | --- | --- |
| ① 用自带 https 的平台 | PaaS / 云托管通常自动分配 https 域名 | 推荐，最省事 |
| ② 域名 + 免费证书 | 解析域名到服务器，用 Let's Encrypt 签证书，Nginx 反向代理 | 自建服务器时用 |
| ③ 前端也降级为 http | 不推荐，静态托管一般强制 https | —— |

> 走路径 C 自建服务器时，**没有域名基本走不通**（自签证书浏览器会红警告）。所以域名约 30~60 元/年是自建方案的隐形成本。

### 阶段 5：修改前端指向并重新构建

1. 修改 `common/config.js:25`，把 `BASE_URL` 改成公网后端地址：

```js
// 【强制】部署到公网必须改这一行
// ⚠️ 末尾不带斜杠；必须是 https（前端为 https 时，http 会被浏览器拦截）
export const BASE_URL = 'https://你的后端域名/api/v1'
```

> ⚠️ 这是**配置项改动**，不是业务逻辑改动。但改完会影响本地开发环境，建议先把原值记下来，或改完部署后立刻改回。

2. 重新构建 H5 产物（当前 `h5-preview/` 已过期）：

```powershell
cd .h5build
npm install --ignore-scripts    # 首次或删过 node_modules 后需要
powershell -File build.ps1      # 同步源码 → 编译 → 刷新 h5-preview/
```

### 阶段 6：部署前端静态站并验证

1. 将 `h5-preview/` 部署到静态托管，取得分享链接
2. 验证清单：
   - 打开链接能看到首页，不是"网络连接失败"
   - 注册/登录能收到验证码邮件
   - 课程列表、分类、课程详情能加载出数据
   - AI 助教能流式回复
3. 用手机流量（非 WiFi）访问一次，确认不是只在局域网内可用

## 五、四个必须提前解决的风险

### 风险 1：DeepSeek API Key 会被陌生人消耗 ⚠️ 最严重

简历上的链接是**公开**的。任何拿到链接的人都能调用 AI 助教，**消耗的是你的 API 余额**。链接可能被转发、被爬虫抓到。

**缓解办法（按推荐度排序）**：

1. **在 DeepSeek 控制台设置消费限额**（最有效，零改动）
2. 使用一个专用 Key，只用于演示，与主 Key 分离
3. 增加调用频率限制（需要改后端代码，需你确认后才动）

### 风险 2：邮箱被注册流程刷爆

公开链接 = 陌生人可以反复触发注册，每次都会发验证码邮件。可能导致：邮箱被判定为垃圾邮件发送源而被封、SMTP 配额耗尽。

**缓解办法**：
1. 用专门的演示邮箱，不要用你的主邮箱
2. 检查 `EMAIL_INTERVAL` 的限流值是否足够严格
3. 部署后临时关闭注册入口（需改前端，需你确认）

### 风险 3：数据库被写入脏数据

任何人都能注册账号、创建订单、提交答题记录。**数据库会很快变脏**，且如果将来想拿这个项目做正式演示，数据已经不可信。

**缓解办法**：
1. 定期备份 + 定期重置数据库（`init_db` + `seed` 重新灌一遍）
2. 使用独立于本地开发环境的数据库实例（**不要**让公网后端连你本地的库）

### 风险 4：HTTPS 混合内容拦截

见阶段 4。这是最容易在最后一刻才发现的失败原因。

## 六、三条路径对比

| 维度 | A. PaaS（Railway/Render/Fly） | B. 腾讯云 CloudBase 云托管 | C. 自建海外服务器 |
| --- | --- | --- | --- |
| 自动 HTTPS | ✅ 有 | ✅ 有 | ❌ 需自己配域名+证书 |
| 免备案 | ✅ | ✅（分配的平台域名） | ✅（选海外/香港节点） |
| 运维成本 | 低 | 低 | 高（自己装 MySQL、Nginx、监控） |
| 需要 Dockerfile | 否 | **是**（需新写） | 可选 |
| WebSocket 支持 | ⚠️ 部分平台会断长连接，需实测 | ✅ | ✅ |
| 国内访问速度 | ⚠️ 可能慢或不稳 | ✅ 快 | 香港节点尚可 |
| 费用 | 有免费额度，超出按量 | 按量，有免费额度 | 60~120 元/月（2核4G） |
| 前置条件 | 注册账号，可能需要绑卡 | 需先连接 CloudBase 连接器 | 需购买服务器与域名 |

**推荐**：
- 想最快看到结果、能接受国内访问略慢 → **路径 A**
- 要求国内访问快、愿意写 Dockerfile → **路径 B**
- 已经有服务器，或不想依赖第三方平台 → **路径 C**

## 七、折中方案（强烈建议考虑）

你选的是"完整可用"。但如果目的是**简历展示**，可以考虑这个折中版，效果几乎一样，风险降一个量级：

**做法：保留完整后端，但掐断两条会烧钱/脏库的入口**

| 改动 | 效果 | 是否需改代码 |
| --- | --- | --- |
| DeepSeek 控制台设消费限额 | Key 被刷也不会超额 | ❌ 不需要 |
| 前端预置一个演示账号，支持一键登录 | 面试官无需注册即可体验全部已登录功能 | ✅ 需改前端（需你确认） |
| 临时关闭注册入口 | 杜绝陌生注册与邮件消耗 | ✅ 需改前端（需你确认） |
| AI 助教保留 | 保住项目最大亮点 | ❌ 不需要 |

这样一来：面试官点开链接 → 一键登录 → 浏览课程、学习模块、AI 对话全部可用，而你不会被烧钱、不会被刷邮件、数据库也不会被陌生人写脏。
